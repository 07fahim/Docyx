# Phase 2: Native PDF Extraction Plan

**Goal:** Extract text, geometry, and fonts from native PDFs and render page images, mapping everything to the canonical coordinate system.

## Tasks

<task>
  <id>1</id>
  <title>Page Rendering Module</title>
  <read_first>
    - .planning/ROADMAP.md
  </read_first>
  <action>
    Create `docyx/pdf/renderer.py` using PyMuPDF (`fitz`).
    Implement a `PDFRenderer` class that can take a file stream or path.
    Create a method `render_page(page_num)` that extracts the page as an image (numpy array or PIL Image).
    Crucially: This must render at exactly 150 DPI to match our canonical reference resolution.
  </action>
  <acceptance_criteria>
    - `PDFRenderer` successfully converts a PDF page to a 150 DPI image.
    - `tests/test_renderer.py` confirms image dimension outputs scale correctly.
  </acceptance_criteria>
</task>

<task>
  <id>2</id>
  <title>Native Text & Geometry Extraction</title>
  <read_first>
    - docyx/core/geometry.py
    - docyx/schema/models.py
  </read_first>
  <action>
    Create `docyx/pdf/text_extractor.py`.
    Implement `NativeTextExtractor`. Extract text blocks/words using PyMuPDF.
    Map the raw PyMuPDF bounding boxes (which are at 72 DPI) to our canonical 150 DPI coordinate system using a scaling function.
    Return a list of `TextElement` objects with `confidence=1.0` (exact) and `provenance=native_pdf`.
    Extract typography (font size, font family) if available in the text dict.
  </action>
  <acceptance_criteria>
    - PyMuPDF text boxes are correctly translated to 150 DPI `BoundingBox` objects.
    - Output elements are strongly typed as `TextElement`.
  </acceptance_criteria>
</task>

<task>
  <id>3</id>
  <title>End-to-End Extraction Pipeline</title>
  <read_first>
    - docyx/pipeline/gate.py
    - docyx/pdf/text_extractor.py
  </read_first>
  <action>
    Create `docyx/pipeline/extractor.py`.
    Implement the `DocyxPipeline` orchestrator:
    1. Initialize the `TextLayerGate`.
    2. For each page:
       - Run `gate.check_page()`.
       - Render the page image regardless of the gate outcome.
       - If the gate passes, run `NativeTextExtractor`.
       - Assemble the `Page` model. If gate fails, assign `status=failed`, populate `errors` with `NO_TEXT_LAYER`, and leave `elements=[]`.
    3. Return the fully assembled `Document`.
  </action>
  <acceptance_criteria>
    - Pipeline successfully orchestrates the gate, renderer, and text extractor.
    - Mixed documents return partial results accurately per the error model requirements.
  </acceptance_criteria>
</task>

## Verification

### Must Haves
<must_haves>
  <truths>
    - All extracted geometry is explicitly scaled from PyMuPDF's native 72 DPI to the canonical 150 DPI.
    - Page rendering happens unconditionally for EVERY page, even if the text-layer gate fails.
    - Native text confidence is hardcoded to `1.0` and type `exact`.
  </truths>
  <prohibitions>
    - Do not attempt to use OCR on gate-failed pages. They must strictly output `elements=[]` and `status=failed`.
  </prohibitions>
</must_haves>
