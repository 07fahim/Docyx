# Phase 1: Foundation Plan

**Goal:** Establish the core schema, coordinate system, provenance/confidence model, error model, and decoupled text-layer gate.

## Tasks

<task>
  <id>1</id>
  <title>Core Geometry & Coordinate System</title>
  <read_first>
    - .planning/PROJECT.md
  </read_first>
  <action>
    Create `docyx/core/geometry.py`. 
    Implement Pydantic models for the canonical geometry system:
    - `BoundingBox`: x, y, width, height (float or int).
    - `Point`: x, y.
    - `Polygon`: list of Points.
    - `Geometry`: unified shape requiring a `bbox`, with optional `polygon` and `rotation`.
    - Document the coordinate system as top-left origin, 150 DPI reference pixels.
  </action>
  <acceptance_criteria>
    - `docyx/core/geometry.py` exists and exposes `BoundingBox` and `Geometry` models.
    - Pydantic validation passes when creating a `Geometry` object with just a `bbox`.
    - `tests/test_schema.py` runs and verifies Geometry serialization.
  </acceptance_criteria>
</task>

<task>
  <id>2</id>
  <title>Provenance & Confidence Models</title>
  <read_first>
    - docyx/core/geometry.py
  </read_first>
  <action>
    Create `docyx/core/metadata.py`.
    Implement Pydantic models for Provenance and Confidence:
    - `ConfidenceType` enum: `exact`, `detected`, `inferred`.
    - `Confidence` model: `value` (float 0.0-1.0) and `type`.
    - `ProvenanceSource` enum: `native_pdf`, `layout_model`, `table_model`, `geometry_inference`, `manual`, `ocr` (reserved), `visual_inference` (reserved).
    - `Provenance` model: `source`, `engine` (optional), `version` (optional), `raw_confidence` (optional).
  </action>
  <acceptance_criteria>
    - Enums strictly enforce the allowed values defined in the v6 design document.
    - Pydantic models successfully validate and serialize the data.
  </acceptance_criteria>
</task>

<task>
  <id>3</id>
  <title>Unified Element & Page Schema (v1.1)</title>
  <read_first>
    - docyx/core/geometry.py
    - docyx/core/metadata.py
  </read_first>
  <action>
    Create `docyx/schema/models.py`.
    Build the main hierarchical Pydantic schema:
    - `PageStatus` enum: `ok`, `partial`, `failed`.
    - `Element`: base class containing `id`, `type`, `geometry`, `confidence`, `provenance`.
    - `TextElement`, `LayoutElement`, `TableElement` subclassing `Element`.
    - `Page`: Contains `page_number`, `status`, `width`, `height`, `source_type` ("born_digital"), `errors` list, `warnings` list, `elements` list, and `diagnostic_elements` list (for v1.1 compliance).
    - `Document`: Top-level container with `schema_version` ("1.1") and `pages`.
  </action>
  <acceptance_criteria>
    - A full `Document` object can be instantiated and exported to JSON matching the v1.1 schema spec.
    - The `Page` model explicitly includes a `diagnostic_elements` field.
  </acceptance_criteria>
</task>

## Verification

### Must Haves
<must_haves>
  <truths>
    - The schema version is strictly encoded as "1.1".
    - `diagnostic_elements` exists as a separate array on the Page schema, distinct from `elements`.
    - Confidence supports the `exact` vs `detected` distinction.
    - Pydantic is used to strictly enforce schema constraints and geometry structures.
  </truths>
  <prohibitions>
    - Do not implement actual PDF parsing (PyMuPDF) in this phase; focus purely on defining the domain models and interfaces.
    - Do not hardcode image formats (PNG/JPG) into the `source_type`; restrict to PDFs/born_digital.
  </prohibitions>
</must_haves>
