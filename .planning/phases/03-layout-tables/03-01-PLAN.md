# Phase 3: Layout, Tables, Reading Order Plan

**Goal:** Detect layout regions, tables, visual elements, and establish reading order, correctly routing results based on the text-layer gate outcome.

## Tasks

<task>
  <id>1</id>
  <title>Layout and Table Analyzer Interfaces</title>
  <read_first>
    - docyx/schema/models.py
  </read_first>
  <action>
    Create `docyx/analysis/layout.py` and `docyx/analysis/tables.py`.
    Implement `LayoutAnalyzer` and `TableAnalyzer` classes.
    For this phase, build the robust interfaces and lightweight heuristic/stub implementations (to ensure component swappability without requiring massive GPU model downloads during development).
    - `LayoutAnalyzer.analyze(image_bytes)` -> Returns `List[Element]` (e.g., `type="heading"`, `type="figure"`) with `ConfidenceType.DETECTED` and `ProvenanceSource.LAYOUT_MODEL`.
    - `TableAnalyzer.analyze(image_bytes)` -> Returns `List[Element]` (`type="table"`) with `ConfidenceType.DETECTED` and `ProvenanceSource.TABLE_MODEL`.
  </action>
  <acceptance_criteria>
    - Analyzers return elements matching the v1.1 schema.
    - Confidence is strictly set to `detected` (probabilistic), not `exact`.
  </acceptance_criteria>
</task>

<task>
  <id>2</id>
  <title>Reading Order Calculator</title>
  <read_first>
    - docyx/schema/models.py
  </read_first>
  <action>
    Create `docyx/analysis/reading_order.py`.
    Implement `ReadingOrderCalculator`.
    It should accept a list of `Element` objects and sort them geometrically (e.g., top-to-bottom, left-to-right XY-cut heuristic) and mutate or return them with a `reading_order` integer field populated.
  </action>
  <acceptance_criteria>
    - Elements passed into the calculator are returned sorted with sequential `reading_order` fields.
  </acceptance_criteria>
</task>

<task>
  <id>3</id>
  <title>Pipeline Routing Integration</title>
  <read_first>
    - docyx/pipeline/extractor.py
  </read_first>
  <action>
    Update `DocyxPipeline.process()` to integrate the new analyzers.
    1. Pass the rendered page image to `LayoutAnalyzer` and `TableAnalyzer`.
    2. If `gate_result.passed`:
       - Combine native text elements, layout elements, and table elements.
       - Pass them through `ReadingOrderCalculator`.
       - Assign the sorted result to `page_model.elements`.
    3. If `not gate_result.passed`:
       - Assign ONLY the layout and table elements to `page_model.diagnostic_elements`.
       - Explicitly do NOT run reading order.
  </action>
  <acceptance_criteria>
    - Gate-passed pages contain text, layout, and tables in `elements` with calculated reading order.
    - Gate-failed pages route layout and tables to `diagnostic_elements` and `elements` remains empty.
  </acceptance_criteria>
</task>

## Verification

### Must Haves
<must_haves>
  <truths>
    - `diagnostic_elements` correctly populates on NO_TEXT_LAYER pages while `elements` remains strictly empty.
    - Reading order is never computed for gate-failed pages.
    - Layout and Table detections use `ConfidenceType.DETECTED`, explicitly distinguishing them from exact native text.
  </truths>
  <prohibitions>
    - Do not download massive ML models (LayoutParser/DocLayNet) which break CI/CD environments; implement the deterministic pipeline logic using stubs/heuristics that fulfill the interface perfectly.
  </prohibitions>
</must_haves>
